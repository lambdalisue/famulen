# 手帳

ある人について AI が知っていることを、Markdown のファイルとして 1 つの Git リポジトリに置く決まり。手帳は、この仕様と、仕様どおりに手帳を扱うライブラリと CLI からなる。

- 手帳は、道具がなくても読めるように書く。このディレクトリを AI に読ませれば、持ち主のことが分かる。
- 手帳には、やりとりから覚えたこと（記憶）と、持ち主が頼りにする事実（記録）を置く。
- 変更は、誰が書いたかとともに Git のコミットになる。

## 形

手帳の形は決まっていて、持ち主が足せるのは記録の種類だけ。

```text
<手帳>/
  README.md              この手帳の読み方
  memory/
    README.md            記憶の層の読み方。まず心得を読むよう案内する
    core.md              心得
    pending.md           保留中の判断
    episodic/            気づき：日ごとのファイル（YYYY-MM-DD.md）
    working/             作業記憶：仕事ごとのファイル
    long/
      semantic/          意味記憶
      procedural/        手続き記憶
      prospective/       展望記憶
    forgotten/           忘却：月ごとのファイル（YYYY-MM.md）
  records/
    workgroups.md        ワークグループ
    <種類>/
      README.md          その種類の読み方と、欄の宣言
      <id>.md            記録 1 件。ファイル名が ID
  .notebook/             道具の作業用。Git に入れない
```

- ファイルは [GitHub Flavored Markdown](https://github.github.com/gfm/) で書き、[Arto](https://github.com/arto-app/Arto) のような Markdown のビューアで読めるようにする。
  - メタデータは、ファイルの先頭の frontmatter（`---` で挟んだ [YAML](https://yaml.org/spec/1.2.2/)。[Jekyll の front matter](https://jekyllrb.com/docs/front-matter/) と同じ形）に書く。
  - 手帳の中のほかのファイルへは、手帳の根からのパスで wiki リンク（[Obsidian の内部リンク](https://obsidian.md/help/links)と同じ形。`[[memory/core]]`、名前を添えるなら `[[memory/core|心得]]`）を書く。
  - 図は [Mermaid](https://mermaid.js.org/) で描き、Mermaid で描きにくいものは Arto の `html-embed` の HTML と CSS で描く。図は中身の決まった絵で、スクリプトは書かない。
- README は説明で、記憶や記録そのものは README に書かない。
- 鍵・トークン・パスワードなどの秘密は書かない。
- 決まった形にないファイルを置いてもよいが、道具はそれを読まず、確かめるときに知らせる。

### 手帳の README

frontmatter は、手帳の形の版だけを持つ。本文には、この手帳の読み方を書く。

```yaml
---
notebook: 1
---
```

## 記憶

記憶は層に分かれる。作業記憶と長期記憶の分類の名前は、心理学の記憶の分け方から取る。

| 層 | 置き場所 | 中身 |
| --- | --- | --- |
| 心得 | `memory/core.md` | いつも最初に読む決まり。150 行まで |
| 保留中の判断 | `memory/pending.md` | 根拠が足りず、決めきれなかった推し量り |
| 気づき | `memory/episodic/YYYY-MM-DD.md` | 日付に関わらず雑に書く受信箱。長期記憶や心得に整理されたら消える |
| 作業記憶 | `memory/working/<名前>.md` | 進めている仕事の今の状態。仕事が済めば消える |
| 意味記憶 | `memory/long/semantic/<名前>.md` | 人や好みなど、事実としての知識 |
| 手続き記憶 | `memory/long/procedural/<名前>.md` | やり方 |
| 展望記憶 | `memory/long/prospective/<名前>.md` | 約束や、これからすること |
| 忘却 | `memory/forgotten/YYYY-MM.md` | 古くなった・置き換わった記憶。戻せる |

### 1 行 1 件の層

心得・保留中の判断・気づき・忘却は、1 件を Markdown のリストの 1 項目に書き、行の終わりに属性を [YAML の flow mapping](https://yaml.org/spec/1.2.2/#742-flow-mappings)（`{キー: 値, …}`）で書く。

```markdown
- 返事は短く、要点を先に {id: m1, src: said, workgroup: [work, personal]}
- 理由に空白を書くときは引用符で囲む {id: m2, src: inferred, reason: "今は別の担当に移った"}
```

- 属性は、項目の文と空白で隔てて行の終わりに置き、1 行の中で閉じる。行の終わりの `{…}` が YAML の mapping として読めないときは、属性ではなく文の一部になる。
- 値は、文字列・数・真偽・並び（[flow sequence](https://yaml.org/spec/1.2.2/#741-flow-sequences)、`[a, b]`）のどれか。
- 文字列に `,`・`:`・`{`・`}`・`[`・`]`・`#` を入れるとき、空白から書き始めるときは、引用符で囲む（[YAML の書き方](https://yaml.org/spec/1.2.2/#73-flow-scalar-styles)のとおり）。

| 属性 | 中身 |
| --- | --- |
| `id` | 記憶ごとに違う ID。手帳の別々のコピーで書いたものとも違う。変えない |
| `src` | `said`（持ち主が言った）・`confirmed`（持ち主が確かめた）・`inferred`（推し量った） |
| `from`・`to` | 有効な期間（`YYYY-MM-DD`）。`to` がなければ今も有効 |
| `ev` | 別々の根拠の数 |
| `workgroup` | 当てはまるワークグループの ID の並び。なければどのワークグループにも当てはまる |
| `supersedes` | 置き換えた記憶の ID |

- 気づきは、書いた日のファイルに、先頭に時刻（`HH:MM`）を書き、属性 `state` に `waiting`（整理を待つ）・`applied`（すぐ長期記憶や心得に入れた）・`record`（記録へ移す。整理を待つ）のどれかを書く。整理を終えた日を属性 `dreamt` に書いた気づきと、`applied` の気づきは、整理する側が消す。
- 保留中の判断は、属性 `need`（決めるのに要る根拠の数）と `against`（食い違う記憶の ID）を持てる。
- 忘却の項目は、属性 `forgot`（忘れた日）・`reason`（わけ）・`was`（元のファイル）を持つ。
- 知らない属性を書いてもよく、道具はそれを消さない。

### 1 ファイル 1 件の層

長期記憶は 1 件を 1 ファイルに書き、欄を frontmatter に、記憶そのものを本文に書く。記憶が触れる人やほかの記録へは、本文から wiki リンクでつなぐ。

```markdown
---
id: m12
summary: 田中さんは甘いものが好き
src: said
from: 2026-09-03
ev: 2
workgroup: [work]
---

[[records/parties/01kasz1m7e0f8d3k6p4v9y2gqa|田中さん]] は甘いものが好き。手土産は和菓子がよい。
```

欄は 1 行 1 件の層の属性と同じで、ほかに `summary`（長期記憶の一覧に出る 1 行）を持つ。

### 作業記憶

作業記憶は、題名の見出しの下に `ここまで`・`次にやる`・`待っている`・`手がかり` の節を持つ文書。

### 使った回数

記憶を使った回数（`uses`）と最後に使った日（`last`）は、属性か frontmatter に書く。使うたびには書かず、道具が `.notebook/` にためておき、記憶を整理するときにまとめて足す。まだ足していない分は、`.notebook/` を消すと失われる。

## 記録

記録は `records/<種類>/<id>.md` に 1 件 1 ファイルで書く。中身は、Markdown として読めば分かるように本文に書く。frontmatter には、仕分けと道具のためのメタデータだけを書く。

```markdown
---
id: 01kat3v8q4zj6m2x9r5c7w1hbn
labels: [定例]
workgroup: [work]
source: コンソールで足した
created: 2026-11-24T10:00:00+09:00
updated: 2026-11-24T12:00:00+09:00
---

# 週の打ち合わせ

- Status: confirmed
- Start: 2026-11-25 14:00
- End: 2026-11-25 15:00
- Calendar: [[records/calendars/01kasx4d2c8n5r7t1v6y3z9wqk|仕事]]
- Location: 渋谷オフィス 3F
- Meeting: <https://meet.example.com/abc>

## Attendees

- [[records/parties/01kasz1m7e0f8d3k6p4v9y2gqa|田中さん]]
  - Email: tanaka@example.com
  - Response: accepted
  - Organizer: yes

## Details

- 議事録の係: 佐藤さん

## Notes

先週の続きから始める。

## Log

- 2026-11-24 10:00 secretary: 会議室を替えた
```

### 記録へのリンク

- 記録へのリンクは、どこでも `[[records/<種類>/<id>|題名]]` と書く。欄の値にも、`Details`・`Notes`・`Log`・メモの本文にも、記憶の文にも書ける。指せるのは、どの種類の記録でもよい。
- `Related` は、どの種類の記録にもある欄で、関わる記録へのリンクの並び。種類の README に宣言しなくてもよい。
- 双方向の関係は片側にだけ書き、逆向きは道具が導く。道具は、ある記録にリンクしている記録を、書かれた欄や節とともに示し、リンクしている記憶（忘却のほか）も示す。
- 欄のリンクに添える題名は、その記録の今の題名。文の中のリンクには、別の名前を添えてもよい。
- 道具で書くときは、ID や題名や code で `[[task-7w1hbn]]`・`[[見積もり]]` のように書いてもよく、道具が上の形に直して書く。型が `link`・`links` の欄では、括弧を省ける。2 件以上に当たるものは、どれも選ばず、候補を示して断る。
- 指す記録がなくなっても、リンクは書かれたまま残り、確かめるときに知らされる。

### メタデータ

どの種類の記録も、frontmatter に次のものを持つ。

| 欄 | 中身 |
| --- | --- |
| `id` | ファイル名と同じ ID。変えない |
| `labels` | 分類のための言葉の並び |
| `workgroup` | 当てはまるワークグループの ID の並び |
| `source` | どこから来たか |
| `created`・`updated` | 作った日時と、最後に道具が書いた日時（[RFC 3339](https://www.rfc-editor.org/rfc/rfc3339)） |
| `google`・`url` | Google のカレンダーにあるものの在りかと、人が開く URL |
| `obsolete`・`obsolete_reason` | 古くなったかもしれない印を付けた日（`YYYY-MM-DD`）と、そのわけ |
| `rested` | 持ち主が相手を休みにした日（`YYYY-MM-DD`） |
| `moved` | この記録の中身を移した先の記録。`records/<種類>/<id>` と書く |

ほかの欄を書いてもよく、道具はその欄を消さない。

- `obsolete` のある記録は、中身が今も正しいかが疑わしい。中身は変えずに付け、確かめたら外す。`Log` を持つ種類では、付けたことと外したことを `Log` にも書く。
- `moved` のある記録は、移した先があるあいだ、もとの形を残すためだけにある。消さないので、その記録へのリンクは切れない。

### ID と code

- ID は [ULID](https://github.com/ulid/spec) を小文字で書いたもの。同じミリ秒に作っても、乱数の部分は毎回作り直す（ULID の仕様の monotonic は使わない）。
- 人が呼ぶ code は、種類の語と ID の末尾 6 文字（`task-7w1hbn`）。ファイルには書かない。その種類のなかで 1 件に決まらないときは、決まるまで末尾を長く取る。
- ID を受け取る道具は、code も受け取る。2 件以上に当たる code には、どれも選ばず、候補を示す。
- 題名が変わったら、道具は手帳の中のそのリンクに添えた題名のうち、前の題名と同じものを直す。
- 手帳の別々のコピーは、Git で 1 つにする（下の「同期」）。ファイルを上書きする同期では、片方の変更が失われる。

### 本文

- 構造は GitHub Flavored Markdown の構文で見る。コードブロックや引用の中の `#` や `-` は、見出しや項目ではない。
- 最初の見出しが題名。
- メモは、題名の下がすべて本文。ただし、題名のすぐ下のリストの最初の項目が、リンクだけを並べた `Related` なら、それは欄で、本文はその後から。
- ほかの種類は、次のものをこの順に持つ。題名のほかは、なくてよい。読むときは、順が違ってもよい。
  - 題名のすぐ下のリスト：決まった欄。1 項目が `欄: 値` の 1 つ。
  - 種類が宣言した節（上の例の `Attendees`）：欄の集まりか、欄を持つ項目の並び。
  - `Details`：持ち主が決める任意の欄。書き方は決まった欄と同じ。
  - `Notes`：自由な Markdown。
  - `Log`：経過。1 件を `- <日時> <書いた人>: <文>` の 1 項目に書く。
- 節は `##` の見出しで始める。上のほかの見出しは、前の節の一部として読む。題名のすぐ下のリストのほかに、最初の節の前に書いたものは `Notes` として読む。
- 道具は、`Notes` の中に上の節と同じ名前の `##` の見出しを書かせない。
- 並びの値は、`, ` で区切って 1 行に書くか、入れ子のリストに書く。値に `,` が入るときは、入れ子のリストに書く。
- 長い値は、字下げした Markdown として次の行から続けられる。
- 項目の並びの節では、項目の文が最初の欄の値で、ほかの欄は入れ子のリストに書く。
- 日時は `YYYY-MM-DD HH:MM`。その記録に `Timezone` があればその時刻、なければ持ち主の現地の時刻として読む。
- 欄の名前は大文字と小文字を区別しない。宣言にない欄も、道具は消さない。

### 種類の README

`records/` にディレクトリを足すと、記録の種類が増える。種類の `README.md` の本文にはその種類の読み方を書き、frontmatter には code の語と、本文に書く欄を宣言する。

```yaml
---
code: holding
fields:
  Status: [ordered, owned, lent, released]
  Category: text
sections:
  Acquired: {On: date, Price: money}
  Deadlines: [{What: text, On: date, Reminded: flag}]
---
```

- `fields` は、題名の下のリストに書く欄。文字列の並びは、選べる値。
- `sections` は、節として書くもの。`{…}` は欄の集まりで、1 つだけの並びに入れると、その欄を持つ項目の並び。
- 文字列は型で、`text`・`number`・`flag`（`yes`・`no`）・`date`（`YYYY-MM-DD`）・`date-or-minute`（`YYYY-MM-DD` か `YYYY-MM-DD HH:MM`）・`money`（額と [ISO 4217](https://www.iso.org/iso-4217-currency-codes.html) の通貨。`398000 JPY`）・`url`・`list`（言葉の並び）・`link`（wiki リンク）・`links`（wiki リンクの並び。`link:tasks` のように、指す種類を決められる）・`any`（形を問わない）のどれか。`text` には wiki リンクも書ける。
- `body: free` と書いた種類は、メモと同じく、題名の下が `Related` のほかすべて本文になる。
- 欄は、書いていなくてもよい。`code` を書かなければ、ディレクトリ名が code の語になる。
- 標準の種類の欄と節は、`README.md` に書かれていなくても使える。
- 宣言のない種類も、メタデータと `Related`・`Details`・`Notes`・`Log` だけで使える。

### 標準の種類

手帳を作るとき、次の種類が README とともに置かれる。

| 種類 | code の語 | 中身 |
| --- | --- | --- |
| `tasks` | `task` | タスク |
| `routines` | `routine` | 決まった時刻に繰り返すタスク |
| `memos` | `memo` | メモ |
| `events` | `event` | 予定 |
| `calendars` | `calendar` | 予定を分けるカレンダー |
| `parties` | `party` | 人と、会社・チームと、グループ |
| `holdings` | `holding` | 手元にある物、あった物 |
| `contracts` | `contract` | ライセンス・サブスクリプション・回線や保険 |

下の表の欄のほかに、どの種類も `Related` を持つ。メモの欄は `Related` だけ。

#### タスク

| 欄 | 中身 |
| --- | --- |
| `Status` | `pending`（まだ）・`in_progress`（進めている）・`waiting`（待っている）・`done`（済んだ）・`cancelled`（やめた） |
| `Assignee` | 誰がやるか。`owner`（持ち主）、`secretary`（AI の補佐役）、`worker`（ほかのエージェントに委ねる）、相手へのリンク |
| `Priority` | `high`・`normal`・`low`。なければ `normal` |
| `Start`・`Due` | 始める日時と期日 |
| `Finished` | 済んだか、やめた日時 |
| `Waiting for` | 何を待っているか |
| `Parent` | 親のタスクへのリンク |
| `Blocked by` | これが済むまで進められないタスクへのリンクの並び |

`Assignee` が `worker` のタスクは、`Notes` に頼みを書き、`Delegation` の節にどう委ねるかを書く。

| `Delegation` の欄 | 中身 |
| --- | --- |
| `Runner` | 何に委ねるか。`adroit`（Adroit のセッション）か `agent`（道具を絞ったエージェント）。書かれていなければ委ねない |
| `Connection` | Adroit のつなぎ先。一つしかなければ書かなくてよい |
| `Directory` | 働くディレクトリの絶対パス。`adroit` には要る |
| `Worktree`・`Base` | 新しいワークツリーで働くか、その元の版 |
| `Agent`・`Agent model` | セッションのエージェントとモデル |
| `Permissions` | `default` か `read_only` |
| `Tools` | `agent` に渡す道具の名前の並び |
| `Files` | `agent` に読ませる手帳のファイルの並び。手帳の根からのパスか wiki リンク |

`Directory`・`Tools`・`Files` は `agent` に、`Connection`・`Directory`・`Worktree`・`Base`・`Agent`・`Agent model`・`Permissions` は `adroit` に効く。

```markdown
# ログインの失敗を直す

- Status: pending
- Assignee: worker
- Priority: high

## Delegation

- Runner: adroit
- Directory: /home/me/src/api
- Worktree: yes

## Notes

ログインが二度目に失敗する。原因を調べて直し、テストを足す。push はしない。
```

```markdown
# 見積もりの返事をまとめる

- Status: waiting
- Assignee: owner
- Due: 2026-11-28 17:00
- Waiting for: 田中さんの返事
- Blocked by: [[records/tasks/01kasz7b2k9c4f6h8j1m3p5rtv|見積もりを集める]]
```

子のタスク、これを待つタスク（blocking）、逆向きの関わりは、ほかの記録から導く。`Blocked by` に `done` でも `cancelled` でもないタスクがあれば、そのタスクはブロックされている。

#### 定期タスク

`Notes` は、そのたびに何をするか。

| 欄 | 中身 |
| --- | --- |
| `Schedule` | いつ。cron の 5 欄（分 時 日 月 曜日）の並び。どれかに当たれば回になる。cron に `,` があれば入れ子のリストに書く |
| `Timezone` | `Schedule` を読むタイムゾーン（[IANA の名前](https://www.iana.org/time-zones)） |
| `Start`・`Until` | この日時より前とあとの回はない |
| `Enabled` | `no` なら止めてある |
| `Assignee` | 誰がやるか。タスクと同じ |
| `Managed by` | 決めた人。`owner` か `secretary` |
| `Skip` | 飛ばす回の時刻の並び |

`Skip if` の節には、回を飛ばす条件を並べる。どれかに当てはまれば飛ばす。項目は、タスクへのリンク（`Status` に並べた状態のどれかにあるあいだ）か、`previous unfinished`（前の回がまだ済んでいないあいだ）。

```markdown
## Skip if

- previous unfinished
- [[records/tasks/01kasz7b2k9c4f6h8j1m3p5rtv|見積もりを集める]]
  - Status: pending, waiting
```

#### 予定

| 欄 | 中身 |
| --- | --- |
| `Status` | `hold`（仮押さえ）・`tentative`（仮）・`confirmed`（決まった）・`cancelled`（取りやめ）。なければ `confirmed` |
| `Start`・`End` | 始まりと終わり。両方が日付だけなら終日で、`End` の日を含む |
| `Timezone` | `Start` と `End` を読むタイムゾーン |
| `Calendar` | カレンダーへのリンク |
| `Busy` | `no` なら、その時間は空いている |
| `Response` | 持ち主の出欠。`accepted`・`declined`・`tentative`・`needs_action` |
| `Location`・`Map`・`Meeting` | 場所、地図の URL、会議の URL |
| `Repeat` | 繰り返しの規則。[RFC 5545 の RRULE](https://www.rfc-editor.org/rfc/rfc5545#section-3.3.10) の値 |

| 節 | 項目の文 | 欄 |
| --- | --- | --- |
| `Attendees` | 相手へのリンクか、名前 | `Email`・`Response`・`Organizer`・`Optional` |
| `Exceptions` | 繰り返しの回のもとの始まり | その回だけ違うもの。`Title`（題名）・`Status`・`Start`・`End`・`Busy`・`Response`・`Location`・`Map`・`Meeting`・`Note`（備考） |

Google のカレンダーにある予定は、書き足すことがあるときだけ記録になる。メタデータの `google` にその予定の ID、`url` にその URL を書き、時刻や参加者は書かない。

繰り返す予定は、全部の回を 1 ファイルに書く。規則にない時刻の `Exceptions` は、その時に加わる回。

```markdown
## Exceptions

- 2026-12-02 14:00
  - Status: cancelled
- 2026-12-09 14:00
  - Start: 2026-12-10 14:00
  - End: 2026-12-10 15:00
```

#### カレンダー

| 欄 | 中身 |
| --- | --- |
| `Color` | 色 |
| `Default for` | 新しい予定をここに入れるワークグループの並び |

`Show` の節には、ワークグループごとの出し方を並べる。項目の文はワークグループの ID、欄は `Mode`（`show` は出す、`faint` は薄く出す、`hide` は出さない）。書かれていなければ `show`。

Google のカレンダーなら、メタデータの `google` に `<つなぎ先>/<カレンダーの ID>` を書く。その予定は Google にあり、手帳には写さない。

#### 相手

| 欄 | 中身 |
| --- | --- |
| `Kind` | `person`（人）・`org`（会社・チーム）・`group`（ゆるい集まり） |
| `Aliases` | 題名のほかの名前や愛称の並び |
| `Birthday` | 誕生日 |
| `Status` | `current`（いま）・`resting`（長く出てこないので休み）。なければ `current` |
| `Last seen` | 最後に出た日 |
| `Added by` | 足した人。`owner` か `secretary` |

| 節 | 項目の文 | 欄 |
| --- | --- | --- |
| `Member of` | 属する会社やグループへのリンク | `Role`（役目） |
| `Relations` | 相手へのリンクか、持ち主を指す `me` | `As`・`Inverse` |
| `Accounts` | サービス | `Handle`（そのサービスでの ID）・`Confirmed`（確かめたか）・`How`（どうつないだか） |

```markdown
# 田中太郎

- Kind: person
- Aliases: たなっち, Tanaka Taro

## Relations

- me
  - As: 部下, 友人
- [[records/parties/01kasz9d4f6h8j1m3p5r7t9vxb|佐藤花子]]
  - As: 夫婦
```

- `As` は、項目の相手から見てこの人が何かを表す言葉の並び。`me` の `部下, 友人` は、持ち主の部下で友人。
- `Inverse` は、この人から見て項目の相手が何かを表す言葉の並び。なければ `As` と同じ（夫婦など）。
- 会社やグループに属する人は、`Member of` から導く。
- `Accounts` の `Confirmed` が `no` のものは推し量っただけ。

## 道具

ライブラリと CLI は、この仕様どおりに手帳を扱う。

- 手帳を作る。なければ、README・層・標準の種類とともに Git のリポジトリとして作られる。
- 記憶と記録を読む・書く・消す。書くと、書いた人の名前でコミットになる。コミットに入るのは道具が変えたファイルだけで、ほかの人がまだコミットしていない変更は入らない。
- 外で書き換えた分を、書いた人の名前でコミットする。
- 確かめる。手帳がこの仕様と種類の宣言どおりに書かれているかを見る（下の「確かめる」）。
- 探す。記憶と記録から、言葉で探す（下の「検索」）。
- 索引と、まだ手帳に足していない使った回数は `.notebook/` に持つ。索引は手帳からいつでも作り直せ、手帳と食い違えば手帳が正しい。手帳が外で書き換えられても、次に読むときに索引が作り直される。
- 道具がつながる先は、持ち主が決めた、同じ手帳の Git だけ（下の「同期」）。外の情報から手帳を作るときは、道具を使う人や AI が自分で外を読み、道具で書く。

### 確かめる

ライブラリと CLI（`famulen-notebook check`）は、手帳の Markdown が決まりどおりかを見る。手帳全体のほか、名指したファイルだけも見られる。確かめるだけでは、何も書き換えない。

見つけたものは、ファイル・行・決まりの名前・わけ・重さを持つ。CLI は人が読む形と JSON で出し、誤りがあれば失敗として終わる。

| 重さ | 意味 | 決まり |
| --- | --- | --- |
| 誤り | 道具が正しく読めないか、手帳に書いてはならない | 読めない frontmatter、記録のメタデータの誤り（ID が ULID でない、ファイル名と違う、記憶や記録の ID の重なり、日付でない `obsolete`、記録を指さない `moved`）、題名がない、選べる値や型に合わない欄、同じ欄や節の重なり、形に合わない項目、時刻の前後の逆転、自分にたどり着く親子とブロック、読めない種類の宣言・ワークグループ、指す先がないか 1 つに決まらない wiki リンク、種類の合わないリンク、秘密らしい文字列 |
| 注意 | 読めるが、決まりから外れている | 決まった形にないファイル、宣言にない欄、節の順、知らないワークグループ、決まった形でない記録へのリンク、リンクに添えた題名の食い違い、両側に書かれた関係、行数を超えた心得 |

- メモの本文は自由で、見るのはメタデータ・題名・`Related`・リンク・秘密だけ。`Notes` の中身も、見るのはリンクと秘密だけ。
- 直し方が一つに決まるものは、求められたときだけ道具が直す（`famulen-notebook check --fix`）。節と欄の順、節と欄の名前の大文字と小文字、日時の書き方、欄のリンクに添えた題名、1 件だけを指す code・題名・ID で書いたリンク（記憶の中のものも）がこれに当たる。値の意味は変えず、直した分は道具の書き込みと同じくコミットになる。
- 道具で書くときも同じ決まりで見て、誤りになる書き込みは、わけとともに断る。前からある別の誤りは、書き込みを妨げない。
- 手で書いたファイルに誤りがあっても、道具は読める所を読み、読めない所を消さない。

### 検索

ライブラリと CLI は、手帳の中を探す口を持つ。探し方は増やせ、どれも同じ口から使える。

- 探すものは、言葉と、絞り込み（記憶の層、記録の種類、当てはまるワークグループ `workgroup`、欄の値、日付の範囲）。絞り込みだけでも探せる。
- 結果の 1 件は、どのファイルの何か（パスと ID）、題名か `summary`、言葉が当たったあたりの抜き書き、当たりの強さを持ち、強い順に並ぶ。
- 最初の探し方は、言葉が文に含まれるかを見る全文検索。日本語の文も、分かち書きなしで探せる。
- 意味の近さで探す探し方（ベクトル検索など）は、あとから足せる。足しても、探す口と結果の形は変わらない。どの探し方で探すかは、探す側が選べる。
- 探すための索引は `.notebook/` に持ち、手帳から作り直せる。手帳が外で書き換えられても、次に探すときに作り直される。
- 忘却の層は、求められたときだけ探す。

### コミット

手帳のコミットは、誰が、何を使って、何をもとに書いたかを残す。履歴を見れば、どの変更を AI が書いたか、どのモデルで書いたかが分かる。

- コミットの作者（author）は、書いた人。AI が書いたときは、その AI を名乗る名前とアドレス。
- コミットの本文の終わりに、[Git の trailer](https://git-scm.com/docs/git-interpret-trailers) でメタ情報を書く。

  | trailer | 中身 | 書くとき |
  | --- | --- | --- |
  | `Co-authored-by` | 一緒に書いた人や AI の名前とアドレス（[GitHub の書き方](https://docs.github.com/en/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/creating-a-commit-with-multiple-authors)）。人の頼みで AI が書いたときの頼んだ人など | 書いた人のほかにいるとき。何人でも |
  | `Notebook-Tool` | コミットを作った道具の名前と版（`famulen-notebook-cli 0.1.0`） | いつも。道具が自分で書く |
  | `Notebook-Agent` | 書いた AI が動いていたアプリやエージェントの名前と版（`Claude Code 2.1.0`） | AI が書いたとき |
  | `Notebook-Model` | 書いた AI のモデルの ID（`claude-opus-5-5`） | AI が書いたとき |
  | `Notebook-Source` | 何をもとに書いたか（会話、受け取ったメッセージ、読んだファイルなど） | 分かるとき。何個でも |

  ```text
  task-7w1hbn「見積もりの返事をまとめる」を足した

  Co-authored-by: Alice <alice@example.com>
  Notebook-Tool: famulen-notebook-cli 0.1.0
  Notebook-Agent: Claude Code 2.1.0
  Notebook-Model: claude-opus-5-5
  Notebook-Source: slack:C024BE91L/1700000000.000100
  ```

- `Notebook-Tool` のほかは、道具を使う人や AI が道具に渡す。道具は、渡されたものをそのまま書き、推し量って足さない。
- 手帳の外で書き換えられた分を道具がコミットするときも、同じ trailer を付ける。

### 同期

手帳の別々のコピーは、持ち主が決めた Git のリポジトリを通して 1 つにする。

- `famulen-notebook clone <URL>` で作ったコピーは、道具が自動で同期する。ほかの手帳は、Git の remote があっても、道具がつながることはない。
- 読む前に、しばらく取り込んでいなければ取り込む。書く前に取り込み、書いた後に送る。求められればいつでも同期する（`famulen-notebook sync`）。常駐するものは要らない。
- 相手に届かないときは、読むのは手元の版で続け、書いたものは手元のコミットに残り、次の同期で送られる。どちらも警告を出す。
- 両方で変わったときは 1 つにまとめる。1 行 1 件の層は、項目を `id` ごとにまとめ、別々に足した項目はどちらも残る。同じ項目や同じ所を別々に変えたときは、どちらも選ばず、手帳を変えずに、ぶつかったファイルを知らせる。
- 取り込みは、まだコミットしていない変更を消さない。
- ぶつかったままのあいだ、読むのは手元の版で続け、そのたびに警告を出す。書いたものと求めた同期は、相手に断られたときと、ぶつかったときは、手元のコミットを残し、わけとともに失敗として終わる。

## テストで押さえること

- 手帳がなければ、README と層と標準の種類とともに Git のリポジトリとして作られ、二度目には何もコミットしない
- 手帳を作るとき、持ち主のまだコミットしていない変更はコミットに入らない
- 属性付きの項目と、frontmatter のある長期記憶と記録は読み書きでき、知らない属性や欄も残る
- 長期記憶の一覧には、各ファイルの `summary` が出る
- 別々のコピーで書いた記憶の ID は別々になる
- 記録の ID はファイル名で、手帳の外を指す ID は断られる
- 同じミリ秒に作った記録の ID は、末尾まで別々になる。code は 1 件に決まる長さまで延び、2 件以上に当たる code には候補が返る
- 題名が変わると、その記録へのリンクに添えた前の題名が直り、持ち主が付けた別の名前は残る
- コードブロックや引用の中の、節や欄に見える行は、節や欄にならない
- 欄を 1 つ書き換えても、ほかの行は 1 文字も変わらない
- `Notes` の中のほかの見出しは `Notes` のまま読み戻され、`Log` に足しても `Notes` は変わらない
- 片側に書いた関係は、逆向きにもたどれる
- 決まった欄・節・`Details` は本文に書いて読み戻せ、人が書いた順や宣言にない欄も残る
- 読めない欄があっても、道具はその行を消さず、確かめるときに知らせる
- `,` の入った値も、並びとして読み戻せる
- 宣言した欄と節の型が確かめられる
- 繰り返す予定は、ずらした回・取りやめた回・加わった回を含めて回に分けられる
- 種類のディレクトリを足すと、その種類の記録が読み書きでき、README の宣言で欄が確かめられる
- 索引は手帳から作り直され、外での書き換え・足したファイル・消したファイルが次に読むときに反映される
- 読めないファイルは索引から外れ、ほかの記録は読める
- 記憶を使っても手帳のファイルは変わらず、整理のときに使った回数がまとめて足される
- コミットには作った道具の名前と版が trailer で残り、渡された一緒に書いた人・AI のアプリ・モデル・もとにしたものも trailer で残る
- 古くなったかもしれない印は、どの種類の記録にも付けられ、付けても外しても書いてある事実は変わらない
- 確かめると、決まりごとに、外れたファイルが行とわけとともに知らされ、何も書き換わらない
- 道具が作った手帳と、道具が書いた記録を確かめると、何も知らされない
- 名指したファイルだけを確かめても、ほかのファイルへのリンクや ID の重なりが見られる
- 注意だけなら成功として、誤りがあれば失敗として終わる
- 直すと、直し方が一つに決まるものだけが直り、もう一度直しても何も変わらない
- メモの本文と `Notes` は、直しても、1 件だけを指すリンクの形のほかは変わらない
- code・題名・ID で書いたリンクは、ID と今の題名の形で書かれ、付けた別の名前とコードの中は残る
- 2 件以上に当たる名前のリンクは候補とともに断られ、前からあるものは書き込みを妨げない
- どの種類の記録も、宣言がなくても `Related` でどの種類の記録にもつなげる
- 種類の決まった欄の名前は、その種類の記録だけを指す
- 記録にリンクしている記録と記憶が、欄・節・文のどこからかとともに索引から出る
- 誤りになる書き込みは、わけとともに断られ、前からある別の誤りは妨げない
- 手帳を作るとワークグループのファイルも置かれ、書いて読み戻せる。読めないものは確かめるときに知らされる
- 言葉で探すと、その言葉を含む記憶と記録が当たりの強い順に、抜き書きとともに出る。日本語の文の中の言葉も当たる
- 層・種類・ワークグループ・欄の値・日付で絞り込むと、当てはまるものだけが出る
- 外で書き換えた・足した・消したファイルは、次に探すときの結果に反映される
- 忘却の層は、求めたときだけ結果に出る
- clone した手帳は、読む前に取り込まれ、書くと相手に届く
- 2 つのコピーで同じ日に足した気づきは、どちらも残る
- 同じ項目を別々に変えるとぶつかったファイルが知らされ、手帳は変わらず、手元のコミットは残る
- 相手に届かなくても読み書きでき、届くようになると送られる
- 取り込みで、まだコミットしていない変更は消えない
- 相手に断られた書き込みは手元に残り、わけとともに失敗になる
- clone していない手帳では、CLI はどこへもつながない
