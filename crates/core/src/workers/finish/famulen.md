1. `AGENTS.md` のとおりに書けているかを確かめ、`just ci` を通す。コンソールに見えるものを変えたなら `just e2e` も通す。
2. `main` からの差分を `code-review-codex` スキルでレビューし、指摘を直す。直したあとの見直しも含めて、レビューは 2 回までにする。2 回目でも残る指摘は、直さずに PR の本文に書く。ただし、正しさや安全にかかわる指摘が残るなら、マージも反映もせずに、そのことを伝えて終える。
3. 一つの意図につき一つの PR を作る。push してよい。
4. CI を見張り、どれか一つでも落ちたら、ほかのジョブを待たずに原因を調べて直し、push し直す。`main` とぶつかったら、最新の `main` に載せ直す。
5. CI がすべて通ったらマージする。マージしてよい。マージする権限がなければ、PR の URL を伝えて終える。
6. このマシンの Famulen がこのリポジトリのチェックアウトから動いていれば、最新の `main` を反映する。してよい。そうでなければ飛ばす。
   - 先に、同じリポジトリで動いているほかのセッションに、動かし直すことを知らせる。
   - 動いているチェックアウトに手を付けかけの変更があれば触らず、そのことを伝えて終える。
   - ビルドに失敗したら動かし直さない。
   - バックエンドの `/health` とコンソールが応え、変えたことが効いていることを確かめる。

どの手順でも、往復のたびにそれまでの会話を読み直すので、呼び出しの数と取り込む出力を少なくする。

- 待つものは 1 回の呼び出しで終わりまで待つ。CI は `gh pr checks --watch --fail-fast` を一度だけ呼ぶ。VM の中のビルドやテストは、終わるまで返らない 1 回の呼び出しで走らせる。様子を何度も見に行かない。
- `just ci`・`just e2e`・ビルドの出力は、失敗した箇所と末尾だけを取り込む（`set -o pipefail; just ci 2>&1 | tail -n 40` や、失敗の行を絞る `rg`）。パイプでつないでも、通ったかどうかは元のコマンドの終了コードで確かめる。
- ファイルは要る範囲だけを読む。
