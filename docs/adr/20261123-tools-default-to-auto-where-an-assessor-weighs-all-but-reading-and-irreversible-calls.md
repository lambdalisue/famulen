# 道具の権限の既定は自動で、見極めのエージェントが読む以外を判断し、取り返しのつかないものは必ず確かめる

状態：採用

## 背景

主人が権限を選んでいない書く道具をすべて確認にすると、主人が頼んだとおりの小さな書き込みでも、呼ぶたびに主人の答えを待つ。確認が多すぎると、主人は中身を読まずに承認するようになり、確認が守るはずのものを守れなくなる。

一方で、書く道具をまとめて許可にすると、メールを外の人へ送る、予定を消すといった、あとから取り消せないものまで尋ねずに通る。

## 決定

主人が何も選んでいない道具の権限は「自動」にする。自動の道具の呼び出しは次のように裁く。

- 読むだけの道具は、モデルを使わずに通す。
- 取り返しのつかないもの、外の人を巻き込むもの、何に届くかを中身から読み取れないもの（シェル）は、必ず主人に確かめる。どれがそうかは、道具が自分について言う印（サービス定義や MCP の注釈、Famulen 自身の API の定義）と道具の名前から決め、モデルには決めさせない。
- それ以外は、呼ぶたびに見極めのエージェントが、道具と中身、主人の直前の頼み、記憶の短いまとめを読んで判断する。頼まれたとおりで、取り返しがつき、外の人を巻き込まないときだけ通し、そうでなければ主人に確かめる。
- 見極めが答えられないとき（モデルがない、一日の上限に達した、モデルが失敗した）は確かめる。

主人が道具ごとに選んだ許可・確認・禁止は、自動より先に効く。見極めの判断と理由は、ゲートウェイの控えに残る。

## 検討した他の案

- 読むだけでない道具は、すべて確認にする。確認が多すぎて、主人が中身を読まなくなる。
- 書く道具の既定を許可にする。取り返しのつかないものまで尋ねずに通る。
- すべての呼び出しを見極めに任せる。モデルは言葉で言いくるめられ得るので、取り返しのつかないものの線をモデルに預けられない。読むだけの呼び出しにまでモデルを使うと、遅く、高くなる。
- 主人の承認の履歴から、似た呼び出しを通すことを学ぶ。中身が少し違うだけで意味が変わる呼び出し（宛先の違うメール）を見分けられない。

## 結果

- 見極めは、モデルを割り当てる役の一つになり、ほかの役と同じく、モデル・考える深さ・一日の上限を主人が選ぶ。
- 見極めの答えに関わらず確かめるものを見分けるために、サービス定義の道具に、取り返しがつかないか、外の人を巻き込むかの印を書ける。
- ゲートウェイを Famulen なしで使うときは見極めがいないので、自動の道具の書き込みはすべて確かめる。
