# 秘書はサービス定義の変更を出せ、入れるのは主人の許しだけ

状態：採用

## 背景

サービス定義は、コードではなくデータとしてゲートウェイが読む。足りない道具（予定を消す、辞退するなど）は、定義を一つ書き足せば使えるようになる。秘書は足りない道具に気づけるが、定義を変える口がなければ、主人が手で書くまで待つしかない。

一方で、定義はどの API を呼ぶか、どの道具を尋ねずに使うかを決める。秘書が自分で変えられると、秘書が自分の権限を広げられる。

## 決定

秘書は、サービス定義の変更を出せる。変更は、確認の一つとして主人に今の定義との違いを見せ、主人が許したときだけゲートウェイが定義の置き場所に書き込む。秘書が出した変更で、道具が今より尋ねずに使えるようになることはない。

## 検討した他の案

- 秘書がリポジトリを複製し、ブランチで定義を直して変更を送る。主人は変更を読めるが、入るのは次のリリースのあとで、主人の手元だけで要る道具にも、リリースの手間がかかる。
- 秘書が書き込み、主人があとから見る。書き込んだ時点で道具が使えるので、主人が読む前に外へ届く。
- 変更の中で書き込み系の道具の権限も自由に書かせ、主人の許しに任せる。違いを読むのは主人だが、権限の一語は見落としやすく、一度の見落としで尋ねずに書き込む道具が増える。

## 結果

- 定義の変更は、ほかの確認と同じ札・答え・控えに乗る。主人は、変更を禁止にもできる。
- 入った変更は、前の版とともに残り、主人は一つ前に戻せる。
- 足された書き込み系の道具は確認から始まり、尋ねずに使うには主人が権限を変える。
