# Famulen ができることはすべて 1 つの型付きの API にし、コンソールと秘書が同じ API を使う

状態：採用

## 背景

主人は、設定を含めて Famulen のことを秘書に頼んで済ませたい。G2 やスマートフォンからも同じことをしたい。コンソールの操作と秘書の道具を別々に作ると、画面でできることと秘書に頼めることがずれていく。

## 決定

Famulen ができることは、protobuf で定義する 1 つの API にし、Connect の手順で出す。コンソールも秘書も、ほかのチャネルも、この API だけで Famulen を操作する。

秘書には、主人だけに許すもののほかの各操作を、そのまま道具として渡す。道具の説明、読むだけか、確かめるか、主人だけに許すかは、API の定義から決める。

## 検討した他の案

- 画面の操作と秘書の道具を別々に作る。片方にだけ足した機能が、もう片方から使えないままになる。
- 型のない JSON の API にする。画面と秘書とチャネルで同じ形を守る手段がなく、ずれても気づけない。

## 結果

- 画面に足した機能は、主人だけに許すと決めない限り、秘書にも頼める。
- 道具の権限は、API の定義が変わらない限り推し量らずに決まる。
- 画面は API の利用者の一つになり、API の外の操作を持たない。
