# 記憶は層に分けた Markdown として Git に置き、夜の夢で整理する

状態：採用

## 背景

秘書は主人の好みや決まり、進めている仕事の途中経過を、会話をまたいで覚えていなければならない。主人は記憶の中を見て直したい。会話のたびに記憶を書き直すと、記憶が縮んだり、間違いが重なったりすることが研究で知られている。毎回読む記憶が大きいと、指示を忘れやすくなる。

## 決定

記憶は、Git リポジトリに Markdown として置き、気づき（日付に関わらず雑に書く受信箱）、作業記憶（進めている仕事の途中経過）、保留中の判断、心得（毎回読む決まり）、長期記憶、忘却の層に分ける。昼の会話は気づきと作業記憶に書き留め、長期記憶と心得を書き換えるのは夜の夢だけにする。夢が整理した気づきは消し、その日の出来事を記録する層は置かない。夢は小さな変更だけを当て、1 つのコミットにまとめる。長期記憶の分類や作業記憶のような、記憶の種類に当たる層は、心理学の記憶の分け方の名で呼ぶ。

## 検討した他の案

- 1 つの記憶ファイルを会話のたびに書き直す。記憶が縮み、経緯も残らない。
- 夢が整理した走り書きを、エピソード記憶として残す。要るものは長期記憶や夜のログに写しがあり、残りは捨てると決めたもので、読み返す用がない。
- 記憶の専用サービスやベクトル検索を使う。主人が中を読みにくく、置くものも増える。
- 層を脳の部位（海馬）や作り手の言葉で呼ぶ。読む人が名前から層の意味を取れない。

## 結果

- 記憶の変更は、誰がどの入力から変えたかとともに Git に残り、戻せる。
- 主人がはっきり言った決まりや訂正も夢を通る。待つあいだは、気づきのまま会話ごとに秘書に渡るので、すぐ効く。
- 一度覚えたものは、消す代わりに忘却へ移すので、間違って忘れたものも戻せる。
- 消した気づきは、Git の履歴からだけ辿れる。
