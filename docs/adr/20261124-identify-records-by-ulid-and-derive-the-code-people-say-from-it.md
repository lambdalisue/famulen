# 記録は ULID で指し、人が呼ぶ code は ULID から導く

状態：採用

## 背景

記録の ID はリンクと同期が頼る、一意で変わらないものでなければならない。一方で会話や画面では、人が口にできる短い呼び名が要る。1 つの値で両方は満たせない。

## 決定

記録を一意に指す ID は ULID とし、ファイル名にもリンクにもこれを使う。人が呼ぶ code は、種類を表す語と ULID の末尾の数文字から導き、どこにも書かない。code が複数の記録に当たるときは、道具は選ばず、候補を示す。

## 検討した他の案

- 日付や題名を ID に入れる。読みやすいが、内容が変わると ID が嘘になる。
- 短い乱数を ID にする。口で言えるが、別々のコピーで作るとぶつかり得て、確かめる仕組みが要る。
- 種類の 1 文字と連番を ID にする。手帳の別々のコピーで同時に足すとぶつかる。
- 連番の code を記録に書く。最も言いやすいが、重なりの振り直しが要る。
- ULID のハッシュから code を導く。ファイル名を見ても code が分からない。

## 結果

- code が重なっても、リンクや同期は壊れない。
- 題名が変わっても、ID もリンク先も変わらない。
- ファイル名だけでは中身が分からないので、リンクには題名を添え、道具の一覧は題名を出す。
