# 秘書のセッションをスレッドごとに分け、どの入力がどの会話のものかはシステムが持つ

状態：採用（20261121-give-every-input-to-one-resident-session-of-a-swappable-model-cli.md を置き換える）

## 背景

すべての入力を常駐する 1 つのセッションに渡していた。モデルは一歩ごとにそれまでの会話をすべて読むので、主人の一言にも、見張りの一件にも、何日分もの関わりのないやりとりを読み、主人の利用枠の大半がそれに消えた。モデル CLI の圧縮は、モデルの窓がいっぱいになるまで働かない。

## 決定

秘書の会話はスレッドごとに分け、それぞれを別のセッションで続ける。見張り・つなぎ先の知らせ・定期の仕事は、1 件ごとに別の会話にする。どの入力がどの会話のものかは、モデルに覚えさせず、システムが持つ。委ねた仕事の終わり・確認の答え・起床予約は、それを頼んだターンの会話に戻す。

会話をまたいで要るものは記憶が持つ。会話の発言そのものは、道具でいつでも読める。

長くなった会話は、モデルの窓よりずっと手前で圧縮する。

セッションを動かすモデル CLI は差し替えられる部品とし、Famulen はそれに道具（MCP）と権限の判定を渡す。部品は Claude Code 1 つを持つ。ターンは、会話がいくつあっても一度に一つだけ動かす。

## 検討した他の案

- 1 つのセッションのまま、早めに圧縮するだけにする。関わりのない話が混ざった要約を毎回読み、要約のたびに今の話の細部も失う。
- ターンごとに新しいセッションにし、要るものを毎回渡す。同じ話を続けるあいだも読んだものを失い、読み直しにかえって使う。
- どの会話へ戻すかをモデルに指させる。会話を分けると、指すべき会話をそのモデルは知らない。
- 会話を並べて動かす。道具の判定は、動いている入力が一つであることに頼っている。

## 結果

- 会話どうしは互いの中身を知らない。記憶に書かれなかったものは、ほかの会話に伝わらない。
- スレッドの外で続けて話したときの「それ」のために、直近の発言を量を限って渡す。
- 道具は MCP で渡すので、どのモデル CLI でも同じ道具と権限を使える。
- Famulen が再起動しても、どの会話も続きから再開する。
- 会話を移るたびにモデル CLI を起動し直す。
- 夢や見張りのような、会話ではない仕事は、どの会話とも別に動かす。
