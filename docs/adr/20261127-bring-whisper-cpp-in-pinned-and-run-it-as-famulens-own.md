# 手元の文字起こしは、版を固定した whisper.cpp を Famulen が自分のディレクトリに取り、自分で動かす

状態：採用

## 背景

手元で声を文字にするには、主人が実行ファイルとモデルを用意し、サーバーを動かし続け、モデルを登録する必要があった。Famulen は OSS として配られるので、用意の仕方は、相手のマシンに何が入っているかを当てにできず、そのマシンの環境を勝手に書き換えてもいけない。

## 決定

手元の文字起こしには whisper.cpp を使う。実行ファイルもモデルも、主人が頼んだときに、Famulen のデータディレクトリの中にだけ置く。取るものは版と大きさと SHA-256 を Famulen に固定して持ち、合わないものは使わない。取得はゲートウェイを通す。

実行ファイルは、公式の配布がある Linux（x86_64、aarch64）ではそれを使う。公式の配布がない macOS では、固定したソースをそのマシンでビルドする。ビルドに要る CMake がなければ、固定した版を同じディレクトリに取る。コンパイラは Xcode Command Line Tools のものを使い、Famulen は入れない。

サーバーは Famulen の子として動かし、Famulen がどう終わっても一緒に終わる。待ち受けは、このマシンの中だけにする。

## 検討した他の案

- Homebrew で入れる。主人の環境を書き換え、版を固定できず、Homebrew がないマシンでは使えない。
- nix で用意する。nix がないマシンでは使えず、消しても容量が戻るかは store の掃除しだいになる。
- Famulen の配布物に同梱する。使わない人にも重くなり、macOS 向けのビルドを自分たちで配り続けることになる。
- macOS 向けのバイナリを第三者の配布から取る。中身を確かめる拠り所が、whisper.cpp の配布元より弱い。
- 主人に起動してもらい、URL だけを登録する。今までのやり方で、用意の手間が残る。この道は引き続き使える。

## 結果

- 消せば、取ったものはすべて戻る。
- macOS では、最初の用意にコンパイラと、ビルドの時間が要る。
- ほかの OS では、手元の用意はできない。
- 版を上げるには、Famulen の版を上げる。
