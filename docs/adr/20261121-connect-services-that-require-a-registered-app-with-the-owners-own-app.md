# アプリの登録が要るサービスは、主人が一度だけ作ったアプリでアカウントごとに直接つなぐ

状態：採用

## 背景

主人の仕事は Gmail・カレンダー・Slack・GitHub などに散らばり、どれにも仕事と個人のアカウントがある。秘書の役目の中心は、そのどこかで主人に関わることが起きたら、早く気づくことにある。

Google や Slack のように、つなぐ側が作って登録したアプリでしかログインさせないサービスがある。モデルの提供元が登録したアプリ（claude.ai のコネクタ）は手間なく使えるが、1 つのサービスに 1 つのアカウントしかつなげず、モデルを動かさなければ読めない。

## 決定

アプリの登録が要るサービスは、主人が一度だけ作ったアプリで、アカウントごとに直接つなぐ。1 つのアプリを、何個のアカウントやワークスペースにも使う。アプリの情報は Famulen を動かす環境で渡し、コンソールではアカウントを足すことだけをする。

## 検討した他の案

- モデルの提供元のコネクタに任せる。アカウントが 1 つに限られ、読むたびにモデルを動かすので、見張りが遅く重くなる。
- Famulen のアプリを公開し、提供元の審査を通す。主人以外にも配るなら要る。Gmail の審査には有料の評価が毎年要り、主人 1 人には重い。
- Google や Slack の MCP サーバーでつなぐ。Google の MCP サーバーにも自分のクライアントが要る。しかも、見張りに要る「前回から変わった分」を読む口がない。

## 結果

- 主人は、使うサービスのアプリをそれぞれ一度だけ作る。作り方はアプリごとの手順書にあり、AI に頼んで作らせられる。
- 見張りとカレンダーは、モデルを通さずに読める。
- 同じサービスの別アカウントは別のつなぎ先になり、道具の名前もつなぎ先で分かれる。
- モデルを Claude から替えても、つなぎ先はそのまま使える。
