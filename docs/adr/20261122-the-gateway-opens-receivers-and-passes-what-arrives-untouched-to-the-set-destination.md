# ゲートウェイは受け口を開け、届いたものに手を加えず、つなぎ先ごとに決めた宛先へ渡す

状態：採用

## 背景

ゲートウェイの仕事は、外への呼び出しを通し、外から届いたものを受け、そのあいだで秘密を扱い、控えを残すことにある。届いたものの意味を読んで共通の形に写し替えたり、変わった分を自分で読みに行ったりすると、ゲートウェイがサービスごとの意味を知ることになり、サービス定義にロジックが要るようになる。届いたものが何を意味するかを知っているのは、それを使う側である。

## 決定

ゲートウェイは、外が届けてくるものの受け口を開ける。受け口は、ゲートウェイが決めた番地で待ち受ける HTTP の口と、ゲートウェイから外へ張る接続（Socket Mode、Pub/Sub の pull、コマンドの出力など）のどちらか。届いたものは、受け取ったことを確かめたうえで手を加えず、つなぎ先・受け取った時刻とともに、つなぎ先ごとに決めた宛先へ渡す。届いたもののうちどれをいつ渡すかを絞るときは、サービス定義に書いた条件だけに従う。ゲートウェイは届いたものの意味を読まず、自分から外を読みに行くこともしない。

## 検討した他の案

- 届いたものを、ゲートウェイが共通の形に揃えて渡す。使う側はサービスの違いを知らずに済むが、ゲートウェイがサービスの意味を読むことになり、サービス定義に写し方のロジックが要る。
- 外が届けてこないものも、ゲートウェイが決まった間隔で読みに行って渡す。続きの印や読み直しのような、サービスごとの読み方をゲートウェイが持つことになる。

## 結果

- 届いたものの読み方（誰宛てか、何の出来事か）は、使う側が持つ。
- 外が届けてこないものは、使う側がゲートウェイの道具で読む。
- 返事は、使う側が普通の道具の呼び出しとして送る。
- 受け口の番地をどこから届くようにするか（私的なネットワークの中か、外からも届くようにするか）は、ゲートウェイを動かす人が決める。ゲートウェイは口を開けるだけで、届く範囲を決めない。
- 受け口に届いたものは、サービス定義に書いた確かめ方（署名など）で確かめ、確かめられないものは渡さない。
