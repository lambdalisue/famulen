# 外から届いたものは一つのモデルが、本文のあるものは題と要約で選んでから、まとめて一度に読み分け、関わりは記録と記憶だけから判断する

状態：採用

## 背景

主人は、割り当てられたタスクや、持っているものに関わる脆弱性、欲しいもののセールなど、外で起きたことに秘書が先回りしてほしい。外から入るものは 1 日に千件を超え、秘書を動かす賢いモデルに全部を読ませると、すぐに予算を使い切る。

主人が手で書く決まりや関心は、書き直さなければ古くなり、言葉の揺れも拾えない。主人は、関わらないものを秘書に「これは関係ない」と言えば済むと考えている。

## 決定

見張りは、見張るところを読むたびに、届いたぶんをまとめて一つのモデルに一度だけ読ませる。要約のほかに本文のあるもの（フィードの記事など）は、その前に同じモデルが題と要約だけをまとめて見て、関わりそうなものだけ本文を読む。モデルはその一度で、各件が主人に関わるか、どれほど急ぐか、同じ話のまとまり、まとまりごとに秘書へすぐ渡すか朝のまとめに回すかを決める。

関わりの判断には、記録と記憶だけから作った手がかりを使う。主人が手で書く決まりや関心は持たない。主人が選べるのは、どこに届いたものを読むか（メールのラベルやチャットのチャンネル）と、関わるものをどこへ回すかまでで、読んだものの何が関わるかは、いつもモデルが決める。主人が関わらないと教えたことは記憶に入り、夢が手がかりに畳み込む。

## 検討した他の案

- 本文もすべて一度に読ませる。フィードの記事の多くは題で関わりがないと分かり、読む費用が無駄になる。
- 全部を秘書に渡す。費用が大きく、秘書の会話も埋もれる。
- 決まり、小さなモデル、中くらいのモデルと段を重ねる。段ごとにモデルと上限を選ぶ手間が増え、同じものを段ごとに読み直す。関わりと同じ話のまとまりは、並べて一度に読むほうが確かめやすい。
- 主人が書く決まりと関心を手がかりに足す。書き直さなければ古くなり、記憶と食い違う。

## 結果

- モデルを呼ぶのは見張るところを読むたびに一度、本文のあるものがあれば二度までで、届いた件数によらない。
- 1 日の上限に達した日は、それ以上読み分けず、残りを朝のまとめに回す。
- 関わらないものを減らすには、秘書に話すか、判断に「要らなかった」を返す。効くのは夢のあとから。
- 各件の判断とそのわけは、主人が見られる記録に残る。
