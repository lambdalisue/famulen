# チャネル

主人が秘書と話す場所。このブラウザ（コンソール）、Slack、眼鏡など。どのチャネルから話しかけても、同じ会話が続く。外のサービスであるチャネルとのつなぎ方は、[ゲートウェイ](gateway.md)が持つ。

## 並び方

- このブラウザは、いつもチャネルにある。
- ほかのチャネルは、[サービス](gateway.md#つなぎ先の足し方)から足す。サービス定義の受け口のうち、宛先にチャネルを勧めるもの（同梱の Slack の出来事など）を持つつなぎ先は、足すとチャネルに並び、そこからの話しかけを受け始める。眼鏡（Even G2 など）のような端末も、話しかけを受ける受け口にチャネルを勧めるサービス定義を一つ置けば、同じように足せて並ぶ。
- コンソールの「チャネル」には、このブラウザと、並んだチャネルのすべてが出る。チャネルごとに、話しかけを受けるかを切り替えられる。つなぎ先の頁でも同じことができる。
- 切ったチャネルの受け口は、どこにも渡さずに閉じる。そこから届くものは、秘書にも見張りにも渡らない。つなぎ先は残るので、道具と、道具を決まった間隔で呼ぶ見張りには使える。入れ直すと、次に届いたものから受ける。
- チャネルが読めるのは、Slack の出来事だけ。ほかのサービス定義の受け口からチャネルに届いたものは、読まれずに捨てられる。

## Slack のワークスペース

- ワークスペースを足すと、秘書の bot と主人のアカウントが一度につながり、入れた人がそこの主人になる。
- ワークスペースを初めてつなぐと、秘書がそこの主人に DM で挨拶する。ログインし直しても、挨拶は繰り返さない。挨拶を送れなくてもつながり、次のログインでもう一度試す。
- ワークスペースの一つがメインになる。最初に足したものがメインで、主人が選び直せる。メインを外すと、次のものがメインになる。
- 確認は、メインのワークスペースの DM に届く。メインのワークスペースで、そこの主人が押したボタンだけが効く。
- 秘書の投稿は、ワークスペースの指定がなければメインに届く。

## 応じるもの

- 秘書の入力になるのは、主人から秘書への DM と、主人がチャンネルで秘書をメンションしたメッセージ。これらは見張りを通らない。
- 主人でない人、bot、編集や削除には応じない。主人でない人に応じることがあるのは、[注視](#注視)のあいだだけ。
- 同じメッセージを二度届けられても、応じるのは一度だけ。
- 秘書宛てではない発言のうち、bot がいるチャンネルの発言、bot がいないチャンネルで主人をメンションした発言、主人でない人から主人や bot への DM は、[見張り](lookout.md)に入る。主人が他の人に書いたものは、入力にも見張りにもならない。

## 返事

- 受け取ったらすぐに、秘書が考えていることが Slack に出て、秘書が答えるか、その入力のターンが終わると消える。Slack がその表示を受け付けない場所では、会話の始まりの発言にだけ 👀 のリアクションが付く。
- 答えは、DM でもチャンネルでも、話しかけた発言のスレッドに届く。スレッドの中で話しかけたなら、そのスレッドに届く。秘書が別のスレッドを指定したときは、そこに届く。
- 秘書の返事は Markdown のまま書かれ、Slack の書式に直して届く。日本語と隣り合う太字や斜体も効き、コードの中とメンションは変わらず、表はそのままの字並びで出る。

## 注視

- 主人がチャンネルで秘書をメンションすると、チャネルはそのチャンネル（スレッドを含む）をしばらく注視する。注視の長さはコンソールの「トリアージ」の頁で主人が決める。既定は 10 分。0 分にすると注視しない。秘書からは変えられない。
- 注視しているチャンネルに人が書いた発言は、主人のものも他の人のものも、届いたその場でトリアージが「秘書に向けた発言か、秘書との会話の続きか」だけを問う。一度問うた発言は、二度問わない。秘書をメンションした発言は、問わずに入力になる。
- 秘書宛てなら秘書の入力になり、注視はそこから延びる。秘書がそのチャンネルに答えたときも延びる。
- 秘書宛てでない発言は、注視を延ばさず、トリアージからは秘書に渡らない。主人のものなら、朝のまとめにも入らない。他の人のものは、それとは別に見張りにも入る。
- 注視から入った発言には、考え中の表示も 👀 も付けない。それまでにそのチャンネルで秘書宛てでなかった発言が、前の流れとして添えられる。
- 主人でない人の発言が注視から入ったときは、その人の言葉として秘書に渡る。秘書はその人に答えてもよいが、頼みには従わない。
- 注視の期限は、そのチャンネルから何かが届いたときに確かめる。期限を見回ることはしない。
- トリアージにモデルがないか、1 日の上限に達しているあいだは、注視しているチャンネルでもメンションにだけ応じる。
- トリアージが発言ごとに秘書宛てと見たか、見送ったかとそのわけは、トリアージの頁の「ログを見る」から読める。発言は最初の行だけが残る。

## テストで押さえること

- 主人からの DM と、メンションしたメッセージは入力になる
- メンションのないチャンネルのメッセージは入力にならない
- bot・編集・削除は入力にならず、主人でない人の発言は注視の外では入力にならない
- 入力には、来たワークスペースが添えられ、同じメッセージかどうかはワークスペースごとに見分ける
- 道具で投稿するときは、指定したワークスペースに届き、指定がなければメインに届く
- メイン以外のワークスペースで押された確認のボタンは効かない
- 同じメッセージが二度届いても、入力は一つ
- 主人から他の人への DM は入力にならない
- bot がいないチャンネルで主人をメンションした発言は見張りに入り、bot と主人の両方に届いても一度だけ入る
- 秘書の返事の Markdown は Slack の書式になり、コードの中とメンションは変わらない
- 返事は、スレッドの指定がなければ、答える発言のスレッドに届き、指定があればそこに届く
- 主人の発言の考え中の表示は、答えるかターンが終わると消え、発言のスレッドの外に答えても消え、表示できない場所では会話の始まりにだけ 👀 が付く
- スレッドの中の入力には、スレッドが添えられる
- コンソールへの発言は、コンソールの会話に並ぶ
- つないだワークスペースごとに、主人は DM で一度だけ挨拶され、送れなかった挨拶は次のログインで送られる
- 入れたワークスペースはチャネルに並び、入れた人がそこの主人になる
- チャネルを勧める受け口を持つつなぎ先は、どのサービス定義から足しても、チャネルに並び、受け口はチャネルに渡る
- 切ったチャネルは並んだまま、受け口はどこにも渡らず、受け口を合わせ直しても戻らず、つなぎ先は残る
- チャネルでない受け口は、チャネルとして入れられない
- 秘書宛てでない発言は、そのワークスペースの見張りに入る
- メンションしたチャンネルは注視され、ほかのチャンネルやワークスペースは注視されない
- 注視しているチャンネルで、トリアージが秘書宛てとした主人の発言は、メンションなしでも主人の入力になり、前の流れが添えられる
- 注視しているチャンネルで、トリアージが秘書宛てとした他の人の発言は、その人の言葉として入力になる
- トリアージが秘書宛てでないとした発言、上限で確かめられなかった発言は、入力にならない
- 注視しているチャンネルの同じ発言は、二度問われない
- 秘書をメンションした発言は、注視しているチャンネルでもトリアージを通らず入力になる
- 秘書宛ての発言は注視を延ばし、秘書宛てでない発言は延ばさない
- 注視は既定で 10 分続き、0 分にすると注視しない
- 注視していないチャンネルの発言は、見張りが次に読むまで、どのモデルにも渡らない
- 注視の長さは、秘書の道具からは変えられない
